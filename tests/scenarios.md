# 検証の手順と結果

Narke の検証は、Claude Code の非対話モード（`claude -p`）で行う。
人が利用者の役になり、回ごとに答えを書いて、同じセッションを `--resume` で続ける。

## 手順

1. `skills/narke` を `~/.claude/skills/narke` にコピーする。
2. 作業用のフォルダに [fixtures/sample-proposal.md](fixtures/sample-proposal.md) をコピーする。
3. 1回目は、新しいセッション ID を付けて実行する。

   ```bash
   claude -p "$(cat p1.txt)" --session-id <uuid> --output-format stream-json --verbose \
     --allowedTools "Read,Write,Edit,Glob,Grep,Agent,Task,Skill"
   ```

4. 2回目以降は、出力を読んでから答えを書き、`--resume <uuid>` で続ける。
5. 最後の回で「ここまで」と言い、わからないことリストを確かめる。

[fixtures/sample-proposal.md](fixtures/sample-proposal.md) は架空の提案書である。次の8つの欠陥を含む。

| 2 | 「個人顧客に限る」と「法人顧客を含めた全顧客」が食い違う | p.4・p.5 | 判断が未決、または資料に説明がない |

| 4 | 「名寄せ」に定義が無い | p.2・p.4 | 説明できない、または資料に説明がない |
| 5 | 着手の判断を求めているのに、費用が無い | 資料全体 | 資料に説明がない |
| 6 | 着手時期と運用体制が「別途決定」 | p.6 | 判断が未決 |
| 7 | 「3か月で30%削減」と「3か月目は試行」が合わない | p.4・p.6 | 根拠を確認できない |

## 結果: 第2版（2026-10-06・Claude Code・Windows）

第2版では、次の4点を変えた。

- 対話の始めに、「わからない」と答えるように頼む約束を伝える。
- 1回の問いを、最大10問にする。
- 対話の途中では正誤を言わず、理解度レポートで段階評価と訂正をまとめて示す。
- 「30秒で」のような、チャットでは不自然な言い方をやめる。

### 第2版で直したこと

| 問題 | 直したこと |

| 規則では「評価 4 の問いはリストに載せない」としていた。t6 は、資料の欠陥を見抜いた評価 4 の問いをリストに残し、「あなたの理解は正しいが、資料の側が未解決」と書いた | t6 の判断のほうが正しい。「解決」を「利用者がその問いに答えられる状態」と定め、資料の欠陥を見抜いた問いはリストに残す規則にした（references/report.md） |

### 気づいた点（未対応）

### 限界

- 各確認項目を見たのは1〜3セッションである。応答はモデルの出力なので、同じ入力でも毎回同じにはならない。
- 利用者の役は、検証する人が演じた。実際の利用者の答え方は、もっと幅がある。
- 本物の .pptx・.pdf の資料では検証していない。検証用の資料は Markdown である。
- Codex では検証していない。
